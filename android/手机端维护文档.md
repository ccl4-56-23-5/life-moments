# 生活点滴手机端维护文档

当前交付版为 Android 0.1.0-beta.5，面向 Android 9 及以上设备。手机读取电脑发布的整理索引和百度网盘照片；缩略图保留本机缓存，展开后的高清图仅在浏览内存中显示，长按选择下载才保存完整原片。维护时应同时保持目录映射、人物资料、缓存身份与浏览状态的一致性。

双端操作见 [使用指南](../docs/使用指南.md)，完整构建与备份见 [开发与维护](../docs/开发与维护.md)，版本变化见 [版本记录](../docs/版本记录.md)。本文记录 Android 原生与网页之间的实现约定。

## 当前交互约定

- 小图时间线只显示照片，不显示人物人数、姓名或头像。
- 展开的照片显示人物姓名与小头像，点击人物进入对应照片页。大合照首屏最多展示 6 人；资料区首批展示 12 人，可逐批展开及按姓名搜索。照片信息保留人物、批注、相册、拍摄位置与完整云端路径。
- 宽度 720 px 起使用侧边导航，1000 px 起展开大图与资料分栏；窄屏、竖屏或分屏按当前宽度自动调整，关闭大图后重排时间线。
- 打开照片先显示缩略图，停留约 180 ms 后请求高清图；切换或关闭照片取消上一请求并释放高清图内存。默认仅在 Wi-Fi 下自动读取，可通过按钮单独确认移动网络读取。
- 小图和大图均支持长按菜单。按住约 550 ms 弹出菜单，移动超过 12 px 则取消，避免滑动时误下载。
- 界面不展示“只读”字样或徽标。当前版本的人物、相册和批注仍从电脑索引同步；没有新增手机编辑或云端写入接口。
- 页面、大图、按钮和缩放使用 `cubic-bezier(.22,1,.36,1)` 缓动。系统减少动画时取消页面过渡。开屏与电脑一致：抛入小球、三次递减弹跳、展开 Logo，页面就绪后揭示图库。
- 原生网盘连接、下载菜单、迁移选择与配对窗口共用 `NativeUi`。浅灰背景、圆角卡片、蓝色控件和字体与网页保持一致；对话框随可用宽度调整，长内容受高度约束并可滚动，键盘弹出时重排。修改窗口外观应通过共用组件，避免各流程重新分叉。

## 云端读取与目录映射

电脑和手机复用同一个百度应用，通常各自通过设备授权连接。局域网迁移可复制旧手机当前的连接配置和授权快照；它不产生新的独立 OAuth 授权，后续若续期失败应在新设备重新授权。不要在日志、网页或索引中输出密钥、令牌和带令牌的下载地址。

索引目录和原片目录是两个配置。索引通常位于 `/apps/你的应用名称/生活点滴索引`，原片可位于 `/数据备份/照片`。例如相对路径 `2022/示例照片.jpg` 对应 `/数据备份/照片/2022/示例照片.jpg`，文件名仅作示例。`LibraryStore.bindRoot` 校验相对路径与旧根目录的一致性后，仅在手机本机快照中替换前缀，不修改电脑或网盘索引。

照片读取采用父目录分页列表，严格匹配完整路径取得 `fs_id`，再调用 `multimedia/filemetas` 获取缩略图和下载地址。父目录缓存约十五分钟，元信息缓存约六小时；全图库预热最多 64 条路径批量查询文件信息，并与高清请求共享结果。重试预览会清理这两类元信息缓存。不要恢复同名文件猜测或把路径 meta 的响应直接视为包含 dlink。

客户端配置不能增加百度授权范围。OAuth 使用 `basic,netdisk`；目录权限、用户配额和频控由百度账号与应用决定。下载跳转只接受既有百度域名白名单。令牌刷新串行执行并持久化新的 refresh_token。

## 图片缓存与高清浏览

缩略图保存在应用私有 `files/thumbnails-v2`，最多 1 GiB，并保留至少 128 MiB 可用空间。全图库预热达到上限即停止，保持已缓存项，不循环淘汰重下；用户正常浏览的新图可按最近访问时间清理旧项，最近一分钟及正在写入的文件暂时保留。缓存身份包含授权会话、完整云端路径、索引大小和时间。升级会迁移旧 `cache/photos-v1` 的缩略图，清除旧版原片和显示副本缓存。

启动或载入新索引后，ThumbnailWarmup 以两个后台 worker 分批扫描全图库；缓存已存在的照片跳过网络请求。当前缩略图和高清图优先，点击大图会暂停后台在途请求并短暂让路。锁屏、切后台、网络中断、账号未绑定及 Wi-Fi 限制使任务暂停，恢复条件后续跑；暂态错误有限退避重试，缺失原片单独计失败。设置可以手动重试失败项；清理缓存同时暂停自动预热，避免立即全部重下。进度回调节流至约每秒一次，并确保末次完成通知到达。

网页最多复用 96 张缩略图 Blob URL。图片队列最多两个请求，优先处理屏幕内图片，再预取约 900 px 范围。请求使用可取消 fetch 并设 30 秒超时，完成或取消都会释放队列名额。隐藏页面取消在途请求；原生 appResumed 即使未收到 visibilitychange 也会清理旧请求和高清状态，重试当前附近图片，避免页面切换或锁屏把队列一直阻塞。照片编号查找使用 Map；人物头像裁切结果按人物复用。

高清图使用内存下载和 ImageDecoder，单张原片硬限 64 MiB，实际原片预算同时参考堆内存余量。已知文件大小时直接分配目标数组，减少 ByteArrayOutputStream 的扩容与复制。显示最长边限 4096 px，并按像素预算缩小；内存不足时再尝试 2048 px，仍不足则友好提示下载后查看，不能导致应用退出。转换为 sRGB JPEG。当前浏览会话保存一份原始字节与显示副本，关闭或换片后解除引用。原始字节可供用户在同一会话长按下载时复用。高清资源返回 `Cache-Control: no-store`，不写应用原片缓存或系统相册。

失败资源返回真实 404 或 503 状态，并提供本机可读的原因。禁止恢复 HTTP 200 的“预览暂不可用”SVG，这会把失败当成功缓存。Wi-Fi 恢复、关闭 Wi-Fi 限制或重新绑定索引后，会重试屏幕附近可恢复的预览；“原片未备份”需补齐备份后手动重试。

清理缓存会清除本机缩略图、网页图片内存和接口元信息，保留索引与用户明确保存到系统相册的照片。

## 局域网复制设置

两台设备均使用当前新版，处在可互访的同一 Wi-Fi。旧设备进入“扫描局域网设备 → 旧设备：发送设置”，新设备扫描并选择旧设备；mDNS 发现不可用时可输入旧设备显示的地址，IPv6 使用 `[地址]:端口`。热点或路由器客户端隔离仍可能阻止直接连接。

发现服务 `_lifemoments._tcp.` 仅携带随机设备名称和协议版本，不携带密钥。传输会话有效三分钟；双方临时 ECDH 密钥先 commitment/reveal，再派生方向独立的 AES-GCM 密钥和相同六位屏幕验证码。两端都比对并确认后才发送敏感资料。每个帧校验方向、序号和认证标签，拒绝篡改、重放、乱序及过期。取消、切后台或结束后关闭 socket、服务发现、广播和临时密钥。

TransferPayload 白名单包含：网盘 AppKey/SecretKey、目录、当前授权与过期时间；Wi-Fi/全图库缓存选项；索引绑定与同步状态；浏览排序、分组、相册排序；经过 schemaVersion 2 校验的图库索引。缩略图、原片、设备 Keystore 密钥和调试恢复状态不迁移。新设备以自己的 Keystore 重加密凭据，随后从网盘缓存缩略图。压缩传输最多 16 MiB，解压后限索引上限加少量配置空间。

导入前校验完整数据、路径和授权绑定，暂停图片读取；写入错误会恢复旧凭据、首选设置和索引。接收确认不会修改旧设备资料。网页只接触三项浏览首选设置，网盘密钥和令牌始终在原生层。升级 targetSdk 时需重新核对 Android 局域网访问权限与 NSD API；当前为 targetSdk 35。

## 长按下载

Android 10 及以上通过 MediaStore 保存到 `Pictures/生活点滴`。先创建 `IS_PENDING=1` 的隐藏文件，完整写入且长度符合索引后置为 0；失败删除本次创建的文件，避免相册出现半张图片。不需要申请读取整个相册或全部文件的权限。

Android 9 使用 `ACTION_CREATE_DOCUMENT` 让用户选择保存位置。下载保留原片字节和格式，浏览用的 4096 px JPEG 副本不会代替原片。单次下载最多 512 MiB，不会上传、覆盖或移动网盘原片。

维护下载逻辑时，必须继续区分普通浏览与明确的下载菜单操作。普通打开照片不能创建 MediaStore 条目或原片文件。

## 顶部安全区与动画

使用原生 FrameLayout，根据系统栏、屏幕挖孔及输入法区域调整 WebView 的实际边界。不要仅给 WebView 加 padding：网页固定导航的视口不会因此正确缩小。大图和开屏使用相同边界，避免顶部标题或底部按钮进入系统区域。

锁屏或切后台调用 WebView.onPause、取消图片 HTTP 与高清 Future，保留索引和缩略图。解锁回到应用调用 onResume、清理暂态失败、恢复预热并通知网页 appResumed。系统低内存会释放高清图；onRenderProcessGone 返回已处理，移除并销毁不可复用的 WebView，提供原生“重新打开”入口，避免应用直接退出或反复自动重载。

索引与凭据在后台读取，原生开屏先展示。网页 `Mobile.ready()` 表示图库界面已构建，开屏在完成品牌动画后淡出；它不等待全部网络图片加载。过渡仅作用于当前可见的少量元素，不变换整个长时间线及 sticky 祖先，也不在筛选或后台图片更新时重播。

## 构建与交付

从仓库根目录执行，提前配置 `JAVA_HOME` 和 `ANDROID_HOME`：

```powershell
python -m pip install -r requirements.txt
& .\android\build.ps1 -SdkPath $env:ANDROID_HOME -JdkPath $env:JAVA_HOME -PythonPath python
Set-Location ..
npm --prefix tools install
node .\android\tests\ui-test.cjs
node .\android\tests\artifact-check.cjs
& .\android\tests\warmup-test.ps1 -JdkPath $env:JAVA_HOME
& .\android\tests\transfer-test.ps1 -JdkPath $env:JAVA_HOME
```

脚本从环境变量读取 SDK 与 JDK，可通过 `-SdkPath`、`-JdkPath`、`-PythonPath` 覆盖；需要 SDK 35、Build Tools 35、JDK 17+ 与带 Pillow 的 Python。使用 Gradle 8.13 和 Android Gradle Plugin 8.13.2，构建执行 assembleDebug 与 lintDebug。首次构建联网恢复依赖，缓存齐全时可加 `-Offline`。`build.ps1` 会切换到 android 目录，因此上述命令随后返回仓库根目录。

把根目录 `config.example.json` 复制为被 Git 忽略的 `config.local.json`，按需填写自己的 `mapStyleUrl`。未配置在线样式使用空白底图并保留照片位置点。构建仅使用程序生成的 35 张风景插画，不读取个人原片或精确轨迹。

升级需保留包名 `com.lifemoments.reader` 和同一签名。提高 `app/build.gradle` 的 versionCode/versionName，并同步安装包名称、界面版本、README、教程及交付记录。当前包为 debug 签名的个人测试版；正式发布需配置发布签名和百度应用审核。

交付安装包时附便携 HTML 教程、维护文档、验证范围与 SHA-256。源码仓库不保存构建输出；发布二进制使用 GitHub Release 附件。手机凭据、真实索引、个人照片截图、原片、签名文件和设备资料不放入 APK 演示资源或源码提交。

## 验证记录与后续测试

本版界面回归覆盖 320、360、390、430、768、1024、1280、1600 px 视口、平板侧导航与分栏、57 人大合照的分批展开和搜索、连续时间线、日期定位、排序、搜索、人物标签、相册批注、大图缩放、小图无人物标记、展开人物头像、自动高清桥接、长按与滑动取消、Wi-Fi 重试、缓动及减少动画。高清桥接的浏览器用例使用明确的接口替身；锁屏恢复覆盖挂起 fetch 取消、队列恢复和失败照片继续操作；地图使用模拟底图。本次 JVM fixtures 通过 11 项缓存调度、19 项密码协议、13 项生产 socket 和 54 项迁移数据/索引检查。测试不调用真实百度接口，不能代替实体设备检测。Android 模拟器本次未能完成稳定启动，所以新的 Android Keystore 导入、系统 NSD 和原生锁屏恢复未标记通过。

当前 Beta 5 的 assembleDebug、lintDebug 与手机/平板合成界面回归已通过，以上 JVM fixtures 共 97 项。早期真机组件测试验证过索引、凭据、内存解码不写文件、缩略图迁移、MediaStore 未完成文件清理与开屏绘制；这些记录不能代替最新版整机测试。真实百度速度、锁屏后的整机体验、两台实体设备迁移、系统相册保存、HEIF、在线地图及不同方向安全区，仍由新版安装后反馈确认。

`src/debug` 的 `ReaderNativeProbe`、`ReaderDeviceProbe`、`ReaderTransferProbe` 和 `ReaderCloudProbe` 仅用于 ADB 调试。ReaderDeviceProbe 使用独立缓存与未公开的 MediaStore 测试文件，ReaderCloudProbe 默认只读诊断，只有显式 `mode=sync` 才提交索引。调试包开放本应用 WebView 的本机调试通道，release 不含自测入口。

收到反馈时先记录应用版本、Android/WebView 版本、网络类型、所在页面及完整错误文字。图片问题区分缩略图、自动高清和明确下载三条路径；同步问题先核对索引目录、原片根目录、有效授权和 schemaVersion。测试原片缺失或大小不符时，保留旧索引，不猜测同名文件。
